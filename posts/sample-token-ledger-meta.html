要点

  1. 第一条，先搭一本能对账的流水账。blue-big-fish 跑完任务后，把每天的 Token 消耗写入 SQLite 的 data/fish.db。后续判断波动时，先有原始记录，再谈原因。
  2. 第二条，台账主表只有四列：day、stage、model、tokens。分别对应日期、任务阶段、模型和 Token。字段不必复杂，关键是每次调用都能落到同一套结构里。
  3. 第三条，stage 要把任务阶段拆开。screen 是初筛，deep 是深读，diary 是日记，sample 是样片，repurpose 是四渠道改写，radar 是选题雷达。
  4. 第四条，分阶段不是为了表格好看，而是为了定位消耗。一次初筛花多少、一份深读花多少、一条样片花多少，都能沿 stage 回查；只看每日总数，找不到具体负担。
  5. 第五条，再记录每次任务的唤醒情况。blue-big-fish 每次醒来都会留下 wakes 表记录。结合主表 Token，就能分清今天醒了多少次，以及每次醒来承担的任务有多重。
  6. 第六条，Token 数不要二次估算。材料明确说明，计数来自 API 响应原文。做自己的台账时，应直接保存接口返回的输入、输出 Token，并保留字段来源，便于沿调用记录复核。
